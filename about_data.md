# Учебник по данным `is_features_1_min_hackaton`

Этот файл объясняет данные так, как если бы мы изучали задачу с нуля: сначала что происходит на бирже, потом что лежит в файлах, затем как из этих файлов собрать торговый pipeline.

Папка `is_features_1_min_hackaton` содержит готовые признаки по интервалам 1 минута. То есть сырые биржевые события уже агрегированы: нам дали не миллионы отдельных заявок и сделок, а удобные таблицы с ценами, объёмами, стаканом и ликвидностью.

Папка `is_features_5_min_hackaton` устроена так же, только один ряд соответствует 5 минутам.

## 1. Что такое тикер

Тикер - это короткое биржевое имя инструмента.

Например:

| Тикер | Что это может означать |
| --- | --- |
| `SBER` | Сбербанк |
| `GAZP` | Газпром |
| `LKOH` | Лукойл |

В наших данных тикеры являются колонками таблиц. Одна колонка - один инструмент.

## 2. Как устроен каждый parquet-файл

Все parquet-файлы в папке устроены одинаково:

```text
строки  = timestamp, то есть время
колонки = тикеры инструментов
ячейка  = значение одного признака для тикера в эту минуту
```

Пример формы таблицы:

```text
timestamp            SBER     GAZP     LKOH
2024-09-02 10:01     ...      ...      ...
2024-09-02 10:02     ...      ...      ...
2024-09-02 10:03     ...      ...      ...
```

Главное правило:

```text
один файл = один признак сразу для всех тикеров
```

Например, `close_.parquet` содержит цену закрытия для всех тикеров, а `buy_size_.parquet` содержит объём покупок для всех тикеров.

## 3. Что такое минутный бар

На бирже постоянно происходят события:

- кто-то выставил заявку на покупку;
- кто-то выставил заявку на продажу;
- кто-то отменил заявку;
- кто-то совершил сделку.

Чтобы не работать с каждым событием отдельно, события собирают в интервалы. В нашей папке интервал равен 1 минуте. Такой интервал называют минутным баром.

Минутный бар отвечает на вопрос:

```text
Что происходило с инструментом за эту минуту?
```

Например:

- какая была первая цена;
- какая была максимальная цена;
- какая была минимальная цена;
- какая была последняя цена;
- сколько было покупок и продаж;
- какой был стакан заявок;
- насколько цена колебалась.

## 4. Цены OHLC

Первое, что обычно смотрят в рыночных данных, - движение цены.

OHLC - это четыре основные цены за период:

| Термин | Простое объяснение |
| --- | --- |
| `open` | Первая цена в минуте. |
| `high` | Самая высокая цена в минуте. |
| `low` | Самая низкая цена в минуте. |
| `close` | Последняя цена в минуте. |

Файлы:

| Файл | Что внутри |
| --- | --- |
| `open_.parquet` | Цена открытия минутного бара. |
| `high_.parquet` | Максимальная цена сделки внутри минуты. |
| `low_.parquet` | Минимальная цена сделки внутри минуты. |
| `close_.parquet` | Цена закрытия минутного бара. Часто используется для расчёта доходности. |
| `pr_std_.parquet` | Волатильность внутри минуты: насколько сильно цена колебалась. |

Зачем это нужно:

- `close_` удобно использовать для расчёта доходности;
- `high_` и `low_` показывают диапазон движения цены;
- `pr_std_` помогает оценить риск.

Пример доходности:

```python
return_1m = close.pct_change()
```

Если цена выросла со `100` до `101`, доходность примерно равна `1%`.

## 5. Что такое стакан заявок

Стакан заявок - это таблица, где видно, по каким ценам участники готовы купить или продать инструмент.

Есть две стороны стакана:

| Сторона | Смысл |
| --- | --- |
| `bid` | Заявки на покупку. Кто-то хочет купить. |
| `ask` | Заявки на продажу. Кто-то хочет продать. |

Пример стакана:

```text
ASK: продать 100 акций по 101.0
ASK: продать 200 акций по 100.5
---------------------------------
BID: купить 150 акций по 99.5
BID: купить 300 акций по 99.0
```

Самые важные цены:

| Термин | Простое объяснение |
| --- | --- |
| `best_bid` | Самая высокая цена покупки. По ней можно быстро продать. |
| `best_ask` | Самая низкая цена продажи. По ней можно быстро купить. |

Файлы первого уровня стакана:

| Файл | Что внутри |
| --- | --- |
| `best_bid_.parquet` | Лучшая цена покупки. |
| `best_ask_.parquet` | Лучшая цена продажи. |
| `best_bid_size_.parquet` | Объём заявок на лучшей цене покупки. |
| `best_ask_size_.parquet` | Объём заявок на лучшей цене продажи. |
| `bid_high_.parquet` | Максимальная bid-цена внутри минуты. |
| `bid_low_.parquet` | Минимальная bid-цена внутри минуты. |
| `ask_high_.parquet` | Максимальная ask-цена внутри минуты. |
| `ask_low_.parquet` | Минимальная ask-цена внутри минуты. |

## 6. Mid-price и spread

Когда есть `best_bid` и `best_ask`, можно построить две ключевые величины.

### Mid-price

Mid-price - это середина между лучшей ценой покупки и лучшей ценой продажи:

```python
mid = (best_bid + best_ask) / 2
```

Зачем нужен `mid`:

- это приближённая справедливая цена;
- по нему удобно считать идеализированный PnL;
- он не зависит от того, покупаем мы или продаём.

### Spread

Spread - это разница между лучшей ценой продажи и лучшей ценой покупки:

```python
spread = best_ask - best_bid
```

Пример:

```text
best_bid = 99
best_ask = 101
spread = 2
mid = 100
```

Почему spread важен:

- если покупаем быстро, обычно покупаем по `best_ask`;
- если продаём быстро, обычно продаём по `best_bid`;
- разница между ними - первая торговая издержка.

Маленький spread обычно означает, что инструмент ликвидный. Большой spread означает, что торговать дорого.

## 7. Сделки и торговый поток

Стакан показывает намерения участников. Сделки показывают, что реально произошло.

Файлы сделок:

| Файл | Что внутри |
| --- | --- |
| `buy_size_.parquet` | Суммарный объём агрессивных покупок за минуту. |
| `sell_size_.parquet` | Суммарный объём агрессивных продаж за минуту. |
| `buy_trades_.parquet` | Количество buy-сделок за минуту. |
| `sell_trades_.parquet` | Количество sell-сделок за минуту. |
| `buy_vwap_.parquet` | Средняя цена buy-сделок, взвешенная по объёму. |
| `sell_vwap_.parquet` | Средняя цена sell-сделок, взвешенная по объёму. |

Агрессивная покупка - это когда участник хочет купить прямо сейчас и забирает заявки с ask-стороны.

Агрессивная продажа - это когда участник хочет продать прямо сейчас и забирает заявки с bid-стороны.

Если агрессивных покупок больше, можно сказать, что покупатели давят на рынок. Если агрессивных продаж больше, продавцы давят на рынок.

## 8. VWAP

VWAP - это средняя цена, взвешенная по объёму.

Обычная средняя цена считает все сделки одинаково. VWAP учитывает, что большая сделка важнее маленькой.

Пример:

```text
10 акций купили по 100
90 акций купили по 110
```

Обычная средняя между 100 и 110 равна 105. Но почти весь объём прошёл по 110, поэтому VWAP будет ближе к 110.

Зачем нужен VWAP:

- показывает более реалистичную среднюю цену исполнения;
- помогает оценивать качество исполнения заявки;
- используется для анализа крупных сделок.

## 9. Дисбаланс: imbalance

Imbalance - это дисбаланс между покупателями и продавцами.

### Trade imbalance

Показывает, кто сильнее в реальных сделках:

```python
trade_imbalance = (buy_size - sell_size) / (buy_size + sell_size)
```

Интерпретация:

| Значение | Смысл |
| --- | --- |
| близко к `1` | почти весь объём был покупками |
| около `0` | покупки и продажи примерно равны |
| близко к `-1` | почти весь объём был продажами |

### Book imbalance

Показывает, на какой стороне стакана больше объёма:

```python
book_imbalance = (best_bid_size - best_ask_size) / (best_bid_size + best_ask_size)
```

Интерпретация:

- если `book_imbalance > 0`, на bid-стороне больше объёма;
- если `book_imbalance < 0`, на ask-стороне больше объёма.

Это не гарантирует рост или падение цены, но может быть полезным торговым признаком.

## 11. Ликвидность

Ликвидность - это насколько легко купить или продать большой объём без сильного ухудшения цены.

Файлы общей ликвидности:

| Файл | Что внутри |
| --- | --- |
| `total_bid_size_.parquet` | Общий размер заявок на покупку по доступной глубине стакана. |
| `total_ask_size_.parquet` | Общий размер заявок на продажу по доступной глубине стакана. |
| `total_bid_volume_.parquet` | Денежный объём bid-стороны, примерно `price * size`. |
| `total_ask_volume_.parquet` | Денежный объём ask-стороны, примерно `price * size`. |

Простая интерпретация:

- большой `total_bid_size` - много желающих купить;
- большой `total_ask_size` - много желающих продать;
- большой объём с обеих сторон - инструмент более ликвидный;
- маленький объём - крупная заявка может сильно сдвинуть цену.

## 12. Как из данных сделать признаки

Для первого baseline достаточно нескольких признаков:

```python
mid = (best_bid + best_ask) / 2
spread = best_ask - best_bid
spread_rel = spread / mid

trade_imbalance = (buy_size - sell_size) / (buy_size + sell_size)
book_imbalance = (best_bid_size - best_ask_size) / (best_bid_size + best_ask_size)
```

Интуиция:

- много агрессивных покупок может быть сигналом роста;
- много агрессивных продаж может быть сигналом падения;
- большой bid-объём может поддерживать цену;
- большой spread делает торговлю дорогой;
- высокая волатильность означает высокий риск.

## 13. Target на 30 минут

Target - это то, что модель должна предсказать.

В `pipeline.txt` написано `signal 30 min`. Значит можно строить сигнал, который пытается предсказать движение цены на 30 минут вперёд.

Для 1-минутных данных:

```python
target_30m = mid.shift(-30) / mid - 1
```

Смысл:

```text
Берём цену сейчас и цену через 30 строк.
Так как одна строка = одна минута, это цена через 30 минут.
```

Для 5-минутных данных 30 минут - это 6 строк вперёд.

## 14. Торговый сигнал

Торговый сигнал - это правило или модель, которая говорит:

```text
купить / продать / ничего не делать
```

Простой baseline:

- если score высокий, покупаем;
- если score низкий, продаём;
- если score средний, ничего не делаем.

Пример идеи score:

```python
score = 0.45 * trade_imbalance + 0.35 * book_imbalance - 0.10 * spread_rel
```

Это не идеальная финансовая модель, а понятный baseline для хакатона: он показывает связь между данными, сигналом и результатом.

## 15. Backtest

Backtest - это проверка стратегии на истории.

Мы задаём вопрос:

```text
Если бы в прошлом мы торговали по этому сигналу, сколько бы заработали или потеряли?
```

Сначала можно считать PnL по mid-price:

```text
PnL mid = прибыль без учёта реальных торговых издержек
```

Но это оптимистичная оценка. В реальности есть:

- spread cost;
- slippage;
- market impact;
- комиссии.

Поэтому важнее смотреть:

```text
PnL net = PnL mid - торговые издержки
```

## 16. Market impact

Market impact - это влияние нашей собственной заявки на цену.

Пример:

```text
Хотим купить 100 акций.
В стакане по лучшей цене продают только 30.
Оставшиеся 70 придётся покупать дороже на следующих уровнях.
```

То есть крупная заявка ухудшает цену исполнения.

Для оценки impact полезны:

- `best_ask_size_` и `best_bid_size_`;
- `l2_ask_n*_size_` и `l2_bid_n*_size_`;
- `total_ask_size_` и `total_bid_size_`;
- `l2_ask_n*_vwap_` и `l2_bid_n*_vwap_`.

## 17. TWAP

TWAP расшифровывается как Time Weighted Average Price.

Идея очень простая:

```text
Не покупать или продавать весь объём сразу.
Разбить большую заявку на равные части.
Исполнять эти части постепенно во времени.
```

Пример:

```text
Нужно купить 100 000 акций за 30 минут.
TWAP покупает примерно 3 333 акции каждую минуту.
```

Зачем так делать:

- меньше market impact;
- меньше риск сдвинуть цену одной большой сделкой;
- исполнение выглядит реалистичнее.

## 18. Как это связано с заданием

В `pipeline.txt` написано:

```text
1. CSV, bars_1min, bars_30min. signal 30 min
2. M2 Сигнал. pnl mid
3. M3 Бэктест baseline. lambda_t
4. M4 Модель импакта. IS / pnl_net
5. M5 TWAP исполнение
```

Перевод на простой язык:

| Модуль | Что делаем |
| --- | --- |
| M1 | Читаем данные и строим минутные признаки. |
| M2 | Строим торговый сигнал на 30 минут вперёд. |
| M3 | Проверяем baseline-стратегию и считаем `pnl_mid`. |
| M4 | Добавляем spread cost и market impact, получаем `pnl_net`. |
| M5 | Показываем TWAP-исполнение большой заявки. |

## 21. Короткое объяснение на защите

```text
У нас есть минутные признаки по акциям: цены, сделки и стакан.
Мы строим mid-price, spread, дисбаланс сделок и дисбаланс стакана.
На этих признаках генерируем сигнал на 30 минут вперёд.
Сначала проверяем PnL по mid-price, затем вычитаем spread cost и market impact.
Для крупной заявки отдельно показываем TWAP-исполнение и implementation shortfall.
```

Самая короткая версия:

```text
Мы не просто предсказываем цену.
Мы показываем полный путь торгового решения:
данные -> сигнал -> backtest -> издержки -> исполнение.
```
