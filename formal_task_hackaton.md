# Постановка задачи: Поиск и реализация устойчивого торгового сигнала с оптимальным исполнением

## Контекст и цель

Реализовать сквозной pipeline: создание сигнала до оценки качества его исполнения с учётом рыночного влияния (импакта).

Параметры задачи:
- **Бар сигнала**: 5 минут
- **Гранулярность исполнения**: 1 минута (1-мин бары внутри 5-мин бара)
- **Целевой объём исполнения**: Q (выбрать временной период и оценить объемы)
- **Основная сессия**: 10:00–18:30 МСК

---
## 1. Модули и типы входов/выходов

Каждый модуль тестируется независимо.

```
OHLCV + bid_ask (parquet)

     ▼                                      ▼
[М2: Сигнал] ──────────────────────── signal_5min

```

## М3: Бэктест — оценка сигнала по mid (baseline)

### Вход
- `signal_5min`: на баре t → позиция открывается в начале бара t+1
- `bars_5min`: для каждого бара — `open`, `close`
- Параметр: пороговая отсечка сигнала `δ > 0`

### Торговая логика (baseline)
```
pos_t = alpha_{t-1}
```

PnL бара t (исполнение по `open`, выход по `close`, нулевой импакт):
```
pnl_mid_t = pos_t * mid_t+1 / mid_t
```

### Выход: `backtest_baseline`

| Поле          | Тип     |
| ------------- | ------- |
| `bar_end_ts`  | int64   |
| `seccode`     | str     |
| `pos`         | float64 |
| `pnl_mid`     | float64 |
| `cum_pnl_mid` | float64 |

**Это baseline** — PnL без учёта стоимости исполнения.

## М4: Модель рыночного импакта (линейная)

### Модель

Стоимость исполнения объёма `x` (в долях от ADV или нормированного объёма) на одном 1-мин слайсе:

```
cost(x) = a(t) * x
```

где:
- `x` = `participation_rate` = объём нашего ордера / суммарный рыночный объём за минуту
- `a(t)` — коэффициент импакта (калибруется на данных, ориентир: `a ∈ [0.01, 0.05]`)
- Стоимость выражается в долях от цены: относительный сдвиг mid-цены

### Вход
- `bars_1min` (для расчёта participation rate)
- Параметр `a` (задан или оценён из данных, см. дополнительную задачу ниже)

### Выход: `impact_model`

| Поле         | Тип     | Описание                                |
| ------------ | ------- | --------------------------------------- |
| `bar_end_ts` | int64   | Конец 1-мин бара                        |
| `seccode`    | str     |                                         |
| `volume_mkt` | int64   | Рыночный объём за минуту (из bars_1min) |
| `a`          | float64 | Коэффициент импакта                     |

**Оценка оптимального объема портфеля** (дополнительная задача):
- По историческим данным оценить объём портфеля, при котором достигается максимальный `net_pnl` в деньгах, т.к. прибыли от AUM выпукла при фиксированной модели импакта → оптимальный объём определяется.

## М5: Оптимизация исполнения внутри бара

### Постановка

Дано: 5-мин бар t, позиция `pos_t ∈ [-1 +1]` по инструменту `s`.

Целевой объём исполнения: `Q_s` лотов по инструменту `s` (знак определяется `pos_t`).

Внутри 5-мин бара — K = 5 слайсов по 1 минуте.

**Переменные оптимизации**: `q_{s,k}` — объём исполнения на k-м слайсе по инструменту s.

**Целевая функция** (минимизация полной стоимости импакта):

```
min  Σ_s Σ_k  a_s(t_k) * (q_{s,k} / volume_mkt_{s,k}) * q_{s,k} * price_{s,k}
     {q_{s,k}}
```

где `x_{s,k} = q_{s,k} / volume_mkt_{s,k}` — participation rate.

**Ограничения**:

```
(1) Суммарный объём по инструменту:
    Σ_k q_{s,k} = Q_s   для всех s

(2) Нейтральность портфеля (по рублёвой стоимости):
    Σ_s pos_t_s * Q_s * price_s ≈ 0

(3) Нормировка (суммарный объём):
    Σ_s |Q_s| * price_s = X  (заданный AUM в рублях, например 50 млн)

(4) Неотрицательность и ограничение participation rate:
    0 ≤ x_{s,k} ≤ x_max   (например x_max = 0.3)
```

### Аналитическое решение (при однородном a_s и volume_mkt)

При постоянном `a_s` по слайсам оптимальное расписание — **равномерное** TWAP:
```
q_{s,k}^* = Q_s / K   для всех k
```

При неоднородном `volume_mkt_{s,k}` — **VWAP-пропорциональное**:
```
q_{s,k}^* = Q_s * volume_mkt_{s,k} / Σ_k volume_mkt_{s,k}
```

### Оценка качества исполнения

**Implementation Shortfall (IS)** — разница между PnL при исполнении по mid и реальным PnL с учётом импакта:

```
IS_s = Σ_k a_s(t_k) * x_{s,k}^2 * volume_mkt_{s,k} * price_{s,k}
```

**Net PnL** (с учётом стоимости):
```
pnl_net_s = pnl_mid_s - IS_s
```

**VWAP достигнутый**:
```
vwap_fill_s = Σ_k (price_{s,k} + a_s * x_{s,k} * price_{s,k}) * q_{s,k} / Q_s
```

### Выход: `execution_schedule`

| Поле                 | Тип     | Описание                                 |
| -------------------- | ------- | ---------------------------------------- |
| `bar_end_ts_5min`    | int64   | Конец 5-мин бара (идентификатор сигнала) |
| `bar_end_ts_1min`    | int64   | Конец 1-мин слайса исполнения            |
| `seccode`            | str     |                                          |
| `q_slice`            | int64   | Объём к исполнению на слайсе (лотов)     |
| `participation_rate` | float64 | `q_slice / volume_mkt`                   |
| `impact_cost_rel`    | float64 | `a * participation_rate` (в долях цены)  |

### Выход: `execution_summary` (агрегат по баре)

| Поле                       | Тип     |
| -------------------------- | ------- |

## 2. Дополнительная задача: оценка оптимального AUM

Зависимость чистого PnL от суммарного объёма X выпукла (при фиксированной модели импакта):

```
f(X) = PnL_gross(X) - IS(X)
```

Оптимальный объём:
```
X* = α / (2c) = α * ADV / (2a)
```
где:
- `α` — ожидаемая доходность сигнала (в долях) — оценивается из бэктеста
- `c = a / ADV` — нормированный коэффициент квадратичного импакта

**Задача**: по историческим барам оценить `α` (из сигнала), `ADV` (из bars_5min), `a` (калибровка) → вычислить `X*` для каждого инструмента.

## 3. Критерии оценки

| Блок                        | Вес | Критерий                                                    |
| --------------------------- | --- | ----------------------------------------------------------- |
| Квантайзер (М1)             | 10% | Корректность дедупликации, агрегации, краевые случаи        |
| Сигнал (М2)                 | 10% | Корректность disb, EMA, согласованность с бэктестом         |
| Модель импакта (М4)         | 25% | Калибровка `a(t)`, стабильность, интерпретируемость         |
| Оптимизация исполнения (М5) | 35% | Корректность постановки ОЗ, качество расписания, IS vs TWAP |
| Исполнение + перфоманс      | 10% | Скорость, модульность, тесты                                |
| Презентация                 | 10% | Ясность изложения, визуализация результатов                 |

### Метрики

- **Sharpe ratio** накопленного `pnl_net` по барам
- **IS reduction**: `(IS_twap - IS_optimal) / IS_twap` в %
- **Net PnL**: `pnl_net = pnl_mid - IS` (основная метрика оптимизации)
- **Hit rate** сигнала: доля баров с `pnl_mid > 0`

## 6. Независимость модулей

Каждый модуль принимает и возвращает строго типизированные таблицы (pandas DataFrame / numpy array):

```
М1: OrderLog CSV  →  bars_1min, bars_5min, deduped_trades

М4: bars_1min, deduped_trades  →  impact_model (lambda_t per 1min bar)
М5: signal_5min, bars_1min, impact_model  →  execution_schedule, execution_summary
```
