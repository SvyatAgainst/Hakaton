# Учебник по данным и формальному pipeline хакатона

Этот файл объясняет данные и решение последовательно, с учётом уточнённого задания из `formal_task_hackaton.md`.

Главная цель задачи: построить полный торговый pipeline:

```text
данные -> 5-мин сигнал -> baseline backtest -> 1-мин impact model -> execution schedule -> pnl_net / IS
```

Важные параметры из ТЗ:

| Параметр | Значение |
| --- | --- |
| Бар сигнала | 5 минут |
| Гранулярность исполнения | 1 минута |
| Основная сессия | 10:00-18:30 МСК |
| Модель импакта | линейная: `cost(x) = a(t) * x` |
| Participation rate | `x = q_slice / volume_mkt` |
| Ограничение исполнения | `0 <= x <= x_max`, например `0.3` |

## 1. Что лежит в `insample_data`

Есть две папки с одинаковыми признаками:

| Папка | Что означает |
| --- | --- |
| `is_features_1_min_hackaton` | Признаки по 1-минутным барам. Нужны для исполнения и impact model. |
| `is_features_5_min_hackaton` | Признаки по 5-минутным барам. Нужны для торгового сигнала и baseline backtest. |

Все parquet-файлы устроены одинаково:

```text
строки  = timestamp, конец бара
колонки = тикеры инструментов
ячейка  = значение одного признака для тикера в этот бар
```

Пример:

```text
timestamp            SBER     GAZP     LKOH
2024-09-02 10:05     ...      ...      ...
2024-09-02 10:10     ...      ...      ...
2024-09-02 10:15     ...      ...      ...
```

Тикер - это короткое биржевое имя инструмента, например `SBER`, `GAZP`, `LKOH`.

## 2. Почему нужны и 5-мин, и 1-мин данные

Уточнённое ТЗ разделяет сигнал и исполнение:

```text
5-мин данные -> понять, что хотим купить/продать
1-мин данные -> решить, как именно исполнять объём внутри 5-мин бара
```

То есть:

- M2 и M3 работают на `is_features_5_min_hackaton`;
- M4 и M5 работают на `is_features_1_min_hackaton`.

Это важно: нельзя делать весь pipeline только на 1-мин данных, потому что по ТЗ сигнал должен быть именно `signal_5min`.

## 3. Минутный и пятиминутный бар

Бар - это агрегированный кусок времени.

1-мин бар отвечает на вопрос:

```text
Что происходило с инструментом за эту минуту?
```

5-мин бар отвечает на вопрос:

```text
Что происходило с инструментом за пять минут?
```

В данных уже посчитаны цены, объёмы сделок, состояние стакана и волатильность для каждого бара.

## 4. Цены OHLC

OHLC - четыре основные цены внутри бара:

| Термин | Простое объяснение |
| --- | --- |
| `open` | Первая цена в баре. |
| `high` | Максимальная цена в баре. |
| `low` | Минимальная цена в баре. |
| `close` | Последняя цена в баре. |

Файлы:

| Файл | Что внутри | Где используется |
| --- | --- | --- |
| `open_.parquet` | Цена открытия бара. | M3 baseline: вход в позицию. |
| `high_.parquet` | Максимальная цена бара. | EDA, риск, range. |
| `low_.parquet` | Минимальная цена бара. | EDA, риск, range. |
| `close_.parquet` | Цена закрытия бара. | M3 baseline: выход из позиции. |
| `pr_std_.parquet` | Внутрибарная волатильность. | Признак риска и калибровка `a(t)`. |

Простая доходность бара:

```python
bar_return = close / open - 1
```

## 5. Стакан заявок: bid и ask

Стакан заявок показывает, по каким ценам участники готовы купить или продать.

| Сторона | Смысл |
| --- | --- |
| `bid` | Заявки на покупку. |
| `ask` | Заявки на продажу. |

Ключевые термины:

| Термин | Простое объяснение |
| --- | --- |
| `best_bid` | Самая высокая цена покупки. По ней можно быстро продать. |
| `best_ask` | Самая низкая цена продажи. По ней можно быстро купить. |
| `best_bid_size` | Объём на лучшей цене покупки. |
| `best_ask_size` | Объём на лучшей цене продажи. |

Файлы:

| Файл | Что внутри |
| --- | --- |
| `best_bid_.parquet` | Лучшая цена покупки. |
| `best_ask_.parquet` | Лучшая цена продажи. |
| `best_bid_size_.parquet` | Объём на лучшей цене покупки. |
| `best_ask_size_.parquet` | Объём на лучшей цене продажи. |
| `bid_high_.parquet` | Максимальная bid-цена внутри бара. |
| `bid_low_.parquet` | Минимальная bid-цена внутри бара. |
| `ask_high_.parquet` | Максимальная ask-цена внутри бара. |
| `ask_low_.parquet` | Минимальная ask-цена внутри бара. |

Из `best_bid` и `best_ask` строятся две важные величины:

```python
mid = (best_bid + best_ask) / 2
spread = best_ask - best_bid
```

`mid` - приближённая справедливая цена.

`spread` - базовая торговая издержка: быстро покупаем по ask, быстро продаём по bid.

## 6. Сделки и торговый поток

Стакан показывает намерения, а сделки показывают, что реально произошло.

Файлы:

| Файл | Что внутри |
| --- | --- |
| `buy_size_.parquet` | Суммарный объём агрессивных покупок. |
| `sell_size_.parquet` | Суммарный объём агрессивных продаж. |
| `buy_trades_.parquet` | Количество buy-сделок. |
| `sell_trades_.parquet` | Количество sell-сделок. |
| `buy_vwap_.parquet` | Средняя цена buy-сделок, взвешенная по объёму. |
| `sell_vwap_.parquet` | Средняя цена sell-сделок, взвешенная по объёму. |

В нашем pipeline рыночный объём за минуту для M4 считается так:

```python
volume_mkt = buy_size + sell_size
```

Это приближение к объёму рынка в 1-мин баре.

## 7. VWAP

VWAP - средняя цена, взвешенная по объёму.

Если маленькая сделка прошла по 100, а большая по 110, VWAP будет ближе к 110, потому что большая сделка важнее.

В задаче VWAP нужен для двух вещей:

- анализировать среднюю цену сделок;
- оценивать цену исполнения крупной заявки по глубине стакана.

## 9. Общая ликвидность

Ликвидность - насколько легко купить или продать большой объём без сильного ухудшения цены.

Файлы:

| Файл | Что внутри |
| --- | --- |
| `total_bid_size_.parquet` | Общий размер заявок на покупку. |
| `total_ask_size_.parquet` | Общий размер заявок на продажу. |
| `total_bid_volume_.parquet` | Денежный объём bid-стороны. |
| `total_ask_volume_.parquet` | Денежный объём ask-стороны. |

Для исполнения важна простая идея:

```text
чем меньше объём рынка в минуту, тем выше participation rate нашей заявки и тем выше impact
```

## 10. M2: сигнал `signal_5min`

По ТЗ вход M2 - агрегированные 5-мин бары.

Выход должен быть таблицей:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `bar_end_ts` | int64 | конец 5-мин бара |
| `seccode` | str | тикер |
| `value` | float64 | сигнал в диапазоне `[-1, 1]` или NaN |

В нашем baseline сигнал строится из простых признаков:

```python
trade_imbalance = (buy_size - sell_size) / (buy_size + sell_size)
book_imbalance = (best_bid_size - best_ask_size) / (best_bid_size + best_ask_size)
spread_rel = spread / mid
```

Интуиция:

- больше агрессивных покупок - сигнал выше;
- больше bid-объёма в стакане - сигнал выше;
- большой spread и высокая волатильность ухудшают сигнал.

## 11. M3: baseline backtest по mid/open-close

По ТЗ сигнал на баре `t` превращается в позицию на следующем баре:

```text
pos_t = alpha_{t-1}
```

То есть мы не используем будущую информацию.

В baseline считаем PnL без стоимости исполнения:

```python
bar_return = close / open - 1
pnl_mid = pos * bar_return
```

Выход `backtest_baseline`:

| Поле | Тип |
| --- | --- |
| `bar_end_ts` | int64 |
| `seccode` | str |
| `pos` | float64 |
| `pnl_mid` | float64 |
| `cum_pnl_mid` | float64 |

Это оптимистичный baseline: он показывает качество сигнала без импакта.

## 12. M4: линейная модель импакта

По ТЗ impact model работает на 1-мин барах.

Модель:

```text
cost(x) = a(t) * x
```

где:

```text
x = participation_rate = q_slice / volume_mkt
```

`q_slice` - наш объём в минутном слайсе.

`volume_mkt` - рыночный объём за эту минуту.

`a(t)` - коэффициент импакта. В ТЗ ориентир `a in [0.01, 0.05]`.

Выход `impact_model`:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `bar_end_ts` | int64 | конец 1-мин бара |
| `seccode` | str | тикер |
| `volume_mkt` | int64 | рыночный объём за минуту |
| `a` | float64 | коэффициент импакта |

В baseline `a(t)` берётся около `0.03` и немного меняется с волатильностью, но остаётся в диапазоне `[0.01, 0.05]`.

## 13. M5: оптимизация исполнения

Дано:

```text
5-мин бар t
позиция pos_t по инструменту s
целевой объём Q_s
внутри бара есть K = 5 слайсов по 1 минуте
```

Нужно выбрать объёмы `q_{s,k}` по минутам так, чтобы суммарная стоимость импакта была меньше.

Participation rate:

```python
x = q_slice / volume_mkt
```

Ограничение:

```text
0 <= x <= x_max
```

В нашем решении расписание распределяет больше объёма в те минуты, где больше рыночный объём и ниже `a(t)`.

Выход `execution_schedule`:

| Поле | Тип | Смысл |
| --- | --- | --- |
| `bar_end_ts_5min` | int64 | 5-мин бар сигнала/позиции |
| `bar_end_ts_1min` | int64 | 1-мин слайс исполнения |
| `seccode` | str | тикер |
| `q_slice` | float64 | объём исполнения в слайсе |
| `participation_rate` | float64 | `q_slice / volume_mkt` |
| `impact_cost_rel` | float64 | `a * participation_rate` |

## 14. Implementation Shortfall и `pnl_net`

Implementation Shortfall, или IS, - стоимость плохого исполнения относительно идеального mid-price.

По ТЗ:

```text
IS_s = sum_k a_s(t_k) * x_{s,k}^2 * volume_mkt_{s,k} * price_{s,k}
```

Net PnL:

```python
pnl_net = pnl_mid - implementation_shortfall
```

Выход `execution_summary`:

| Поле | Тип |
| --- | --- |
| `bar_end_ts_5min` | int64 |
| `seccode` | str |
| `Q_executed` | float64 |
| `vwap_fill` | float64 |
| `twap_bench` | float64 |
| `implementation_shortfall` | float64 |
| `pnl_mid` | float64 |
| `pnl_net` | float64 |

Дополнительно в notebook считается `is_reduction`:

```python
is_reduction = (IS_twap - IS_optimized) / IS_twap
```

Это показывает, насколько наше расписание лучше простого TWAP по стоимости импакта.

## 15. Как связаны модули

```text
M1: готовые parquet-фичи
    |
    | 5-min bars
    v
M2: signal_5min
    |
    v
M3: backtest_baseline -> pnl_mid
    |
    | 1-min bars + volume_mkt
    v

    |
    v

```

## 17. Что говорить на защите

Короткая версия:

```text
Мы используем 5-минутные признаки для построения сигнала `signal_5min`.
Сигнал применяется со сдвигом на следующий бар, чтобы не было look-ahead bias.
Baseline считает `pnl_mid` без импакта.
Затем на 1-минутных барах строится линейная модель импакта `a(t)`.
Внутри каждого 5-мин бара объём распределяется по пяти 1-мин слайсам.
Мы считаем `implementation_shortfall` и финальный `pnl_net`.
```

Самая короткая версия:

```text
Сигнал принимаем на 5 минутах, исполняем на 1 минуте, затем сравниваем идеальный PnL с реальным PnL после импакта.
```
